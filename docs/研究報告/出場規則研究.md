## 1. 為什麼要做

候選股票只告訴你「買什麼」，沒有告訴你「什麼時候賣」。你的回撤目標是 −25%，上限 −30%（2026-11-19 決定），但系統之前只「顯示」回撤，沒有規則在「控制」回撤。

這份研究回答三個問題：

1. **停損**：從買進價下跌多少就賣，能不能讓回撤變小，又不會常常賣在低點？
2. **移動停損**：從買進後的最高點回落多少就賣，能不能保住獲利？
3. **依大盤減碼**：市場狀態轉壞的當天就減碼，而不是等到月底，能不能避開大跌？

## 2. 規則定義（`ExitRules`）

| 規則 | 內容 |
|---|---|
| 停損 | 收盤價（還原）比買進價低 stop 以上 → 下一個交易日開盤全部賣出 |
| 移動停損 | 收盤價（還原）比買進後最高收盤低 trail 以上 → 下一個交易日開盤全部賣出 |
| 依大盤減碼 | 市場狀態「不好」（空頭，或高波動且加權指數在 200 日均線下）時，總持股只留 regime 比例；狀態好壞轉換的當天立刻重新選股並調整 |
| 選股 | 基礎策略只在每月最後一個交易日（與狀態轉換日）選股；其他日子維持持股，只檢查出場 |
| 停損後 | 被賣掉的股票到下次選股前不會買回 |

- 價格用還原價，除權息不會誤觸停損。
- 每天檢查時，權重差距小於總資產 2% 不交易，避免為了漂移來回買賣（引擎參數 `min_trade`）。
- 成交方式、成本、漲跌停限制與其他研究相同（docs/回測框架.md）。

## 3. 測試設計（事先固定）

**基礎策略**（和網站候選股票同一個模型）：

- `ML:lgbm:60:15:3`：LightGBM 60 日分數前 15 檔，每月調整（模擬追蹤中的策略）。
- `ML:lgbm:60:6:3+D3`：前 6 檔、依波動反比配置，接近小額帳戶依金額配股的結果。

**每個基礎策略各測 15 組**：

| 類別 | 設定 |
|---|---|
| 不加規則 | 基準 |
| 只有停損 | 10%、15%、20% |
| 只有移動停損 | 15%、20%、25% |
| 只有依大盤減碼（每天） | 留 50%、30%、0% |
| 組合 | 停損 15%＋移動 20%＋留 50%；移動 20%＋留 50%；停損 15%＋留 50%；停損 15%＋移動 20%＋留 30% |
| 對照 | 舊的每月依大盤減碼（D2，留 50%） |

**期間**：研究期 2018-01-02～2022-12-30（ML 分數從 2018 才有）用來選；驗證期 2023–2024 用來確認。保留期（2025-01-02～2026-10-30）維持鎖定。

**指標**：年化報酬、Sharpe、最大回撤、Calmar、換手、停損觸發次數，以及 swing 門檻（docs/研究報告/機器學習研究報告.md §2）。

## 4. 選定規則（看到結果前先寫好，避免挑最好看的）

> 使用者確認前為草案。

1. **研究期**：在最大回撤 ≥ −25% 的設定中，選 Sharpe 最高的；如果沒有任何設定達到 −25%，選最大回撤最小、且 Sharpe 不低於「不加規則」的那組。
2. **驗證期**：選出的設定必須同時符合：
   - 最大回撤比「不加規則」小。
   - Sharpe 不比「不加規則」低超過 0.1。
3. **兩段都符合**：把參數寫進 `backend/src/apex/risk.py`，網站上的出場提醒與投入比例改用正式數字。
4. **驗證期不符合**：網站改成只顯示帳戶回撤提醒，不顯示個股停損價，並在這份文件記錄失敗原因。
5. 兩個基礎策略的結論不同時，以 `ML:lgbm:60:6:3+D3`（接近實際帳戶）為準。

### 6.3 解讀

1. **個股停損、移動停損沒有用**：兩個策略、兩段期間都一樣，報酬與 Sharpe 都變差，回撤幾乎沒有改善。可能的原因是：這類股票（模型偏好跌深反彈）常常先跌再漲，停損剛好賣在低點；而大跌通常是整個市場一起跌，停掉一檔、下個月又買進另一檔一起跌的股票。
2. **大盤轉壞當天減碼有用**：前 6 檔策略的研究期最大回撤從 −40.0% 降到 −25.6%，Sharpe 從 0.70 升到 0.74。舊的「每月底才判斷」反而更差（−43.8%），證明關鍵在**當天就反應**。
3. **驗證期無法檢驗大盤減碼**：2023–2024 年沒有出現「市場狀態不好」的日子，所以加不加這條規則，結果完全一樣。
4. 前 15 檔策略的大盤減碼也把回撤從 −33.9% 降到 −25.1%，但年化從 13.6% 降到 9.2%，Sharpe 從 0.63 降到 0.57，代價比較大。

### 6.4 依第 4 節選定規則

- 研究期：沒有任何設定的最大回撤達到 −25%。改選 Sharpe 不低於「不加規則」（0.70）中回撤最小的 → **大盤不好留 50%（`X:-:-:0.5`）**，−25.6%、Sharpe 0.74。
- 驗證期：最大回撤 −10.9%，和「不加規則」**相同、沒有更小**（因為這段期間沒有觸發）；Sharpe 1.80，不低於 1.79。
- 照字面，第 2 項「最大回撤比不加規則小」不成立，屬於第 4 項「驗證期不符合」。但這不是規則被驗證失敗，而是驗證期**沒有機會檢驗**。這是事先沒有想到的情況，交由使用者決定。
- 個股停損與移動停損：兩段期間都變差，不論怎麼決定都不採用。

把 `.github/research-runs.json` 推送到 main 以外的分支，或在 Actions →「策略研究」手動執行並填入參數。單一組合的指令範例：


## 8. 決定（2026-11-21，使用者）

使用者選擇**選項二：兩個都不採用**。

| 項目 | 決定 | 理由 |
|---|---|---|
| 個股停損、移動停損 | 不採用 | 兩個策略、兩段期間都讓報酬與 Sharpe 變差 |
| 大盤轉壞當天減碼 | 不採用 | 研究期有效（回撤 −40.0% → −25.6%），但驗證期沒有觸發、無法確認；使用者接受較大回撤換取較高長期報酬（研究期 5 年 30 萬約 63 萬 vs 57 萬） |
| 持有滿 60 個交易日重新評估 | 保留 | 不是交易規則，只是提醒對照模型的預測期間 |

網站因此：
- 不顯示個股停損價、出場線。
- 市場狀態頁的燈號改成只描述大盤（紅燈「風險高」、黃燈「小心」、綠燈「趨勢向上」），不建議減碼；說明裡寫明「回測發現紅燈時減碼能少賠、但也會少賺，由你決定」。
- 帳戶回撤提醒（−10%／−20%／−25%／−30%）照舊。

`ExitRules`（`+X:…`）與 `min_trade` 保留在研究工具裡，之後如果出現新的市場狀態（例如 2025 年以後的資料解鎖），可以重新檢驗大盤減碼。
