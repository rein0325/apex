## 1. 為什麼要做

候選股票只告訴你「買什麼」，沒有告訴你「什麼時候賣」。你的回撤目標是 −25%，上限 −30%（2026-11-19 決定），但系統之前只「顯示」回撤，沒有規則在「控制」回撤。

這份研究回答三個問題：

1. **停損**：從買進價下跌多少就賣，能不能讓回撤變小，又不會常常賣在低點？
2. **移動停損**：從買進後的最高點回落多少就賣，能不能保住獲利？
3. **依大盤減碼**：市場狀態轉壞的當天就減碼，而不是等到月底，能不能避開大跌？

## 2. 規則定義（`ExitRules`）

| 規則 | 內容 |
|---|---|
| 停損 | 收盤價（還原）比買進價低 stop 以上 → 下一個交易日開盤全部賣出 |
| 移動停損 | 收盤價（還原）比買進後最高收盤低 trail 以上 → 下一個交易日開盤全部賣出 |
| 依大盤減碼 | 市場狀態「不好」（空頭，或高波動且加權指數在 200 日均線下）時，總持股只留 regime 比例；狀態好壞轉換的當天立刻重新選股並調整 |
| 選股 | 基礎策略只在每月最後一個交易日（與狀態轉換日）選股；其他日子維持持股，只檢查出場 |
| 停損後 | 被賣掉的股票到下次選股前不會買回 |

- 價格用還原價，除權息不會誤觸停損。
- 每天檢查時，權重差距小於總資產 2% 不交易，避免為了漂移來回買賣（引擎參數 `min_trade`）。
- 成交方式、成本、漲跌停限制與其他研究相同（docs/回測框架.md）。

## 3. 測試設計（事先固定）

**基礎策略**（和網站候選股票同一個模型）：

- `ML:lgbm:60:15:3`：LightGBM 60 日分數前 15 檔，每月調整（模擬追蹤中的策略）。
- `ML:lgbm:60:6:3+D3`：前 6 檔、依波動反比配置，接近小額帳戶依金額配股的結果。

**每個基礎策略各測 15 組**：

| 類別 | 設定 |
|---|---|
| 不加規則 | 基準 |
| 只有停損 | 10%、15%、20% |
| 只有移動停損 | 15%、20%、25% |
| 只有依大盤減碼（每天） | 留 50%、30%、0% |
| 組合 | 停損 15%＋移動 20%＋留 50%；移動 20%＋留 50%；停損 15%＋留 50%；停損 15%＋移動 20%＋留 30% |
| 對照 | 舊的每月依大盤減碼（D2，留 50%） |

**期間**：研究期 2018-01-02～2022-12-30（ML 分數從 2018 才有）用來選；驗證期 2023–2024 用來確認。保留期（2025-01-02～2026-10-30）維持鎖定。

**指標**：年化報酬、Sharpe、最大回撤、Calmar、換手、停損觸發次數，以及 swing 門檻（docs/研究報告/機器學習研究報告.md §2）。

## 4. 選定規則（看到結果前先寫好，避免挑最好看的）

> 使用者確認前為草案。

1. **研究期**：在最大回撤 ≥ −25% 的設定中，選 Sharpe 最高的；如果沒有任何設定達到 −25%，選最大回撤最小、且 Sharpe 不低於「不加規則」的那組。
2. **驗證期**：選出的設定必須同時符合：
   - 最大回撤比「不加規則」小。
   - Sharpe 不比「不加規則」低超過 0.1。
3. **兩段都符合**：把參數寫進 `backend/src/apex/risk.py`，網站上的出場提醒與投入比例改用正式數字。
4. **驗證期不符合**：網站改成只顯示帳戶回撤提醒，不顯示個股停損價，並在這份文件記錄失敗原因。
5. 兩個基礎策略的結論不同時，以 `ML:lgbm:60:6:3+D3`（接近實際帳戶）為準。

```powershell

```
