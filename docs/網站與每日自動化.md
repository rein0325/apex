## 1. 架構

```
GitHub Actions（台灣時間平日 18:20～22:20 每小時一次，23:50 最後一次）
  ├─ 還原資料庫：Actions 快取（加密）→ 沒有快取時從 Release「db-seed」下載加密快照
  ├─ apex daily --record-paper --site site
  │    ├─ 更新資料（行情、公司行動、籌碼、營收財報、指數、休市日）
  │    ├─ 月底記錄模擬追蹤訊號 → 雜湊承諾寫入 backend/paper/commitments.csv 並推送
  │    ├─ 每天記錄候選股票前 30 名（pick_log）
  │    └─ 產生網站 site/：frontend/ 的畫面＋data.json（市場資訊）、prices.json、h/（公開行情）、
  │       picks.json（候選股票，密碼加密）
  ├─ 加密匯出資料庫 → 存回 Actions 快取（每週五另外更新 Release 備份）
  └─ 發布到 GitHub Pages
你的電腦
  └─ 持股與交易紀錄（personal/，永遠不上傳）、apex portfolio、本機每日報告
```

| 公開（網站或 repo） | 不公開 |
|---|---|
| 各證券最新收盤價與除權息還原比例（prices.json，交易所公開資料） | 「我的持股」頁輸入的交易與現金（只存在你的瀏覽器） |
| 大盤狀態、均線距離、波動、市場寬度 | 持股、交易紀錄（只在本機） |
| 加權報酬指數、0050 近一年走勢與報酬 | 模擬追蹤的個股清單（只存在加密資料庫） |
| 模擬追蹤整體績效（只有策略說明） | 資料庫內容（加密，含第三方資料） |
| 程式碼、研究文件 | 資料庫金鑰（GitHub Secrets） |
| 模擬追蹤訊號的雜湊（backend/paper/commitments.csv） | |

**為什麼不公開個股**：未持有投顧執照公開推薦特定股票，可能違反投顧相關法規，即使標註「不是建議」也一樣。所以模擬追蹤只列整體績效；候選股票（2026-11-20 加入）用密碼加密後才放上網站，只有知道密碼的人能看（docs/候選股票.md §7）。

**雜湊承諾**：每期訊號會算出 SHA-256 雜湊（含隨機 salt）並公開在 `backend/paper/commitments.csv`，由 Actions 的 commit 時間證明「訊號是在結果出來前就記錄的」。日後如果要公開某期名單，連同 salt 一起公布，任何人都能驗證名單沒有事後修改。

## 2. 市場狀態頁

- **一句話結論**（2026-11-21 改版）：紅燈「風險高」（空頭，或高波動且在 200 日均線下）、黃燈「小心」、綠燈「趨勢向上」，以及長期趨勢、漲跌幅度、轉強股票比例三個圖示。燈號只描述大盤，不建議減碼（出場規則研究的決定）。燈號規則收在「燈號怎麼判斷」。
- 近一年走勢、報酬表（紅漲綠跌的色塊）。
- **產業強弱**：近 1 個月最強、最弱各 5 個產業的長條圖，以同產業股票的成交金額加權。
- **資料更新狀態**（平常只顯示一行「資料都已更新」，有問題才列出項目）：
  - 行情、三大法人、融資融券、加權報酬指數：是否更新到應有的交易日。
  - 月營收：11 日起應有上個月的資料。
  - 季財報：最新可用的一季。
- 研究策略的模擬追蹤。

## 2-1. 我的持股頁（holdings.html）

網站上有「我的持股」入口，可以直接在手機上輸入交易紀錄與現金（使用者 2026-11-20 選擇方案 A）。

- **資料只存在那台裝置的瀏覽器**（localStorage），不會傳到 GitHub 或任何伺服器。網站只提供公開的收盤價（prices.json），市值、損益、比重、提醒都在瀏覽器裡計算。
- 計算方式與電腦上的 `apex portfolio` 相同：還原約當股數、平均成本法、手續費 0.1425% 無條件捨去最低 1 元（可設定折扣）、證交稅股票 0.3%／ETF 0.1%／債券 ETF 0%。已用同一組交易比對過，兩邊結果一致。
- **回撤**：瀏覽器拿不到完整歷史股價，所以從開始使用那天起，每次打開時依收盤價累積計算（含現金）。電腦版 `apex portfolio` 才有完整的歷史回撤。
- **備份與同步**：「匯出 CSV」與電腦上的 `personal/trades.csv` 格式相同，可以互相匯入；換手機或清除瀏覽器資料前要先匯出。
- 提醒規則同電腦版：帳戶回撤 −10%／−20%／−25%／−30%、單一個股（不含 ETF）超過 30%、持股可能停止交易或下市。
- **畫面**（2026-11-21 改版）：上方是總資產、回撤條（紅線＝目標 −25%）、股票占總資產比例條。每檔持股一張卡片：右上角一個結論標籤、損益大數字、持有天數條（滿 60 個交易日重新評估）。
- **標籤**：持有滿 60 個交易日顯示「重新評估」；其他時候顯示模型看法（續抱／留意／考慮減碼）；ETF 顯示「長期持有」。
- **不提供個股停損價**：2026-11-21 決定：個股停損、移動停損回測都變差，不採用；大盤轉壞當天減碼在驗證期無法確認，使用者選擇不採用（《研究報告/出場規則研究.md》§8）。
- 共用設定放在 data.json 的 `risk`（後端 `apex/risk.py`）：重新評估天數、大盤是否亮紅燈。

## 3. 排程與失敗處理

- 每次執行都只補缺的資料，重複執行沒有影響。
- 23:50 以前的幾次即使資料還沒到齊，也不算失敗。
- 23:30 最後一次如果資料仍不是最新（`--fail-if-stale`），工作就標示失敗，GitHub 會寄通知信。
- 網站一定標示「資料日」，資料不是最新時會顯示警告（規格書 §5.4）。
- GitHub 官方說明排程可能延遲或略過（2026-11-20 三次都沒觸發），所以改成台灣時間平日 18:20～22:20 每小時一次，23:50 最後一次。
- 推薦紀錄（pick_log）要等各類資料都更新、或當天最後一次執行時才記錄，避免用到不完整的籌碼資料。
- 公開 repo 如果 60 天沒有任何活動，排程會被自動停用；每月模擬追蹤的 commit 可以維持活動。

## 3-1. 雲端測試與研究

- `.github/workflows/test.yml`：每次推送都執行程式風格檢查與全部測試，再用真實資料庫試跑一次每日流程（不更新資料、不發布）。本機 Windows 的「智慧型應用程式控制」會擋 DuckDB，所以測試以雲端為準。
- `.github/workflows/research.yml`：在雲端跑回測研究。手動執行時填入參數，或在 main 以外的分支修改 `.github/research-runs.json` 後推送；每組參數平行執行，結果放在執行摘要與附件。研究結果不寫回資料庫。

## 4. 資料庫怎麼存在雲端

- 完整資料庫約 1.7 GB，匯出成 Parquet（zstd）後約 230 MB，再用 AES-256 加密（`apex snapshot export／restore`）。
- 金鑰只放在 GitHub Secrets 的 `APEX_DB_KEY`，以及你電腦上的 `personal/db_key.txt`（請另外備份一份）。
- **日常**：Actions 快取每次執行都會存一份新的，加密後才存。
- **初始與備份**：Release `db-seed` 的 `apex-db.tar.enc`，每週五由 Actions 更新。快取超過 7 天沒用會被刪除，這時就從這份備份接續。
- 快照只存在 Release 和 Actions 快取，都是加密的。公開 repo 的其他人或 fork 下載了也讀不到。

**本機與雲端是兩份資料庫**：
- 雲端負責每日更新、網站和模擬追蹤。模擬追蹤以雲端為準，本機的 `apex daily` 預設不記錄。
- 本機要看持股報告時，跑一次 `apex update` 或 `apex daily` 更新行情即可。

## 5. 你要在 GitHub 上做的設定（只需一次）

1. **轉為公開**：apex → Settings → General → 最下方 Danger Zone → Change repository visibility → Public。
2. **開啟 Pages**：Settings → Pages → Build and deployment → Source 選「GitHub Actions」。
3. **設定金鑰**：
   - 位置：Settings → Secrets and variables → Actions → New repository secret。
   - Name 填 `APEX_DB_KEY`。
   - Secret 貼上 `personal/db_key.txt` 的內容。
   - 再新增一個 `APEX_VIEW_PASSWORD`：候選股票頁的密碼（自己設定）。
4. **上傳初始快照**：
   - 位置：Releases → Draft a new release。
   - Tag 填 `db-seed`（Create new tag），標題「資料庫加密快照」。
   - 附加檔案 `snapshot/apex-db.tar.enc`（約 240 MB）。
   - 勾選 Set as a pre-release，然後 Publish。
5. **試跑**：Actions → 每日更新 → Run workflow。成功後網址是 `https://rein0325.github.io/apex/`。

## 6. 本機指令

在 `backend/` 目錄執行：

```powershell
python -m uv run python -m apex daily --no-update --site ../site
```

產生網站預覽。因為頁面要讀 data.json，請用本機伺服器開啟（例如在 site/ 執行 `python -m http.server`），不要直接雙擊檔案。

**前後端分工**：
- `frontend/`：畫面，純 HTML、CSS、JavaScript，不需要建置工具。
- `backend/src/apex/site.py`：只產生 `data.json`。
- 要改畫面只動 frontend/；要改資料內容才動後端。

```powershell
python -m uv run python -m apex snapshot export ../snapshot/apex-db.tar.enc
```

手動匯出加密快照前，需要先設定環境變數 `APEX_DB_KEY`。
