## 目錄

```
frontend/            網站畫面（GitHub Pages）：市場狀態、候選股票、我的持股三頁；ui.js 是共用圖示與圖形
backend/             後端（Python）
  src/apex/          資料擷取、回測、研究、持股、每日流程、網站資料
  tests/             測試
  probes/            資料來源探測腳本（研究用）
  paper/             模擬追蹤訊號的雜湊承諾（公開）
docs/                規格與決策文件
  研究報告/           策略與機器學習的研究計畫、研究報告
.github/workflows/   每日更新、雲端測試、雲端回測研究、資料來源探測（GitHub Actions）

personal/            持股、交易紀錄、每日報告、資料庫金鑰（只留本機，不進版本控制）
```

## 開發環境

需要 [uv](https://docs.astral.sh/uv/)。後端指令都在 `backend/` 目錄下執行：

```bash
cd backend
uv sync
uv run python -m pytest
uv run python -m ruff check .
```

在這台 Windows 上，`pytest.exe` 會被系統的應用程式控制原則擋下，所以統一用 `python -m` 執行。若 `uv` 不在 PATH，可改用 `python -m uv`。

2026-11-20 起，Windows「智慧型應用程式控制」也會擋 DuckDB 元件，本機無法讀取資料庫。測試改在 GitHub Actions 的「測試」流程執行：每次推送都會跑單元測試，並用真實資料庫試跑一次每日流程（不更新資料、不記錄、不發布）。

資料擷取（詳見資料層設計 §6）：

```bash
uv run python -m apex update     # 每日更新：行情、公司行動、籌碼、月營收、財報、指數、休市日
uv run python -m apex status     # 資料狀態
uv run python -m apex backtest --strategy buyhold:0050 --start 2016-01-04 --end 2026-11-17 --freq once
```

日常使用（詳見持股與每日報告）：

```bash
uv run python -m apex daily      # 更新資料、產生本機每日報告（personal/reports/）；模擬追蹤由雲端記錄
uv run python -m apex trade --date 2026-11-18 --code 0050 --side buy --shares 100 --price 94.5
uv run python -m apex portfolio  # 持股損益、帳戶回撤、風險提醒
uv run python -m apex paper      # 候選策略模擬追蹤（未通過驗證，僅追蹤）
```

資料來源探測：

```bash
python backend/probes/data_source_probe.py
```

網站預覽（產生 data.json 並複製 frontend/ 到 site/，再用瀏覽器開 site/index.html）：

```bash
uv run python -m apex daily --no-update --site ../site
```
